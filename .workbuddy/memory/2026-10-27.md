## market-pick clist 反封禁加固（agent/src/market_pick/boards.py）

背景：仍是扫描时被 Eastmoney clist 封 IP（日志 ~61 次调用触发 RST），原设计只有
固定 900s 冷却 + 3 连败熔断，冷却到期后立刻用 2 主机×2 重试的"重炮"试探，越试越封。

五层防线（均已实现 + 测试覆盖）：
1. `pz=1000` 大分页：板块清单/成分股一次调用拿全；分页按**实际返回行数**推算，
   防服务端偷偷把 pz 截到 100 导致成分股静默丢失。
2. 全进程自适应闸门（`_gate_wait`/`_gate_note`）：扫描内联与后台 warm-up 共享
   发射槽，基准间隔 8s，失败翻倍至 60s 上限，成功按 0.8 衰减。
3. 升级式熔断：当天第 n 次熔断冷却 = 900s × 2^(n-1)，封顶 8h，±10% 抖动。
4. 熔断状态落盘 `~/.vibe-trading/market_pick/clist_state.json`（wall clock），
   进程重启不再立刻重试。
5. 探针经济：冷却到期后只允许 **1 发** 试探（不重试、不换主机），失败立即再熔断；
   已有失败记录时后续调用一律单发，不再打 4 发重试网。

另外：扫描内联冷拉加了 90s 墙钟预算（`VIBE_TRADING_MARKET_PICK_COLD_SECONDS`），
避免 8s 间隔下冷启动把 HTTP 扫描请求堵 5 分钟；余下交给 warm-up。

新环境变量：`VIBE_TRADING_MARKET_PICK_CLIST_GAP`、`..._COLD_SECONDS`。

测试：tests/test_market_pick.py 45 项全绿（新增 7 项：探针经济、升级冷却、落盘恢复、
失败单发、闸门退避、冷拉预算、pz 被截断时的分页兜底）。ruff clean。
注意：本机 bare Python 环境缺依赖，跑测试前装了 pytest/pandas/fastapi/httpx/httpx2/
rich/python-multipart；全量 tests 收集失败均因缺 fastmcp/defusedxml/yaml 等第三方包，
与本次改动无关。

## 市场优选板块覆盖率（第二轮：为什么还有大量板块没数据）

现象：1001 个板块（496 行业 + 505 概念），只有 300 个有成分缓存，界面只显示 180+。
根因：WAF 大约每窗口只放行 40~70 次 clist，"每板一发"的模型根本跑不完 1000 个板块，
8s 匀速也照样在第 60~73 发被 RST，所以覆盖率永远停在 300 附近。

改动（`agent/src/market_pick/boards.py`）：
1. **批量扫盘** `bulk_fill_members` / `_bulk_sweep`：一次全 A 股 clist
   （fs=沪深京A，fields=f12,f13,f14,f100,f103）拿每只票的行业与概念标签，
   按名称回填所有匹配板块 → 1000 次请求压到 ~6 次。
2. 三道自校验，任一不过立刻丢弃（宁可没有也不写错）：
   `_bulk_plausible`（名称数/去重代码数/中位板块规模）、
   覆盖率 ≥40%（防"只给一级行业"的粗粒度字段）、
   `_bulk_cross_check`（与 per-board 已写缓存逐板块比对，按多数票而非均值）。
3. 不覆盖已有文件；每天最多一次（`members/_bulk_state.json`，aborted 状态 2h 内不重试）。
4. 板块清单请求加 `f6/f3`，warm-up 缺板按成交额降序填（真热点先生效）。
5. `warm_work_pending` 增加"回退到最近缓存清单"，否则今天清单抓不到时 warm-up 根本不启动。
6. `_atomic_write(durable=False)`：批量写 500 个文件 8.2s → 0.69s（缓存文件不需要 fsync）。

模拟（真实 1001 板块清单 + 合成扫盘数据）：一次扫盘 0.69s 回填 505 个板块，
覆盖率 237 → 782。industry 因合成数据与被信任缓存零重叠被正确拒绝 —— 自校验生效。

新环境变量：`VIBE_TRADING_MARKET_PICK_BULK_MIN_MISSING`(25)、`..._BULK_CALLS`(6)。

测试：test_market_pick.py 58 项全绿（新增 12 项：一次调用回填、不覆盖、交叉校验拒绝、
截断丢弃、每日一次、冷板阈值、占位字段拒绝、覆盖率拒绝、多标签概念、成交额排序、
清单记录 turnover、warm_work_pending 回退）。ruff clean。
