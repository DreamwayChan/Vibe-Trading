## 研报表格结构化模块 —— 设计方案

- 产出文档：`docs/design/research-report-tables.md`（482 行，含架构/契约/分阶段/验收指标）
- 背景：`agent/src/tools/doc_reader_tool.py::_read_pdf` 只用 `get_textpage().get_text_range()`，表格退化为数字墙；`_MAX_CHARS=15000` 让研报表格进不了上下文。
- 核心决策：
  - 新增独立工具 `extract_tables`（不改造 `read_document`），理由是预算/依赖/失败模式三重隔离；`src/tools/` 自动发现 `BaseTool` 子类，无需改注册表。
  - 插件式 `TableEngine` Protocol，对齐已有 `src/tools/ocr/engine.py` 范式；docling 走 `docs` extra + lazy import + 硬降级到 heuristic。
  - `read_document` 仅新增 `has_tables_hint` / `table_pages_hint` 两个纯增量字段。
- 关键实测（pypdfium2 5.12.1，`.venv`）：
  - `FPDF_PAGEOBJ_LINE` / `RECT` **不存在**，5.x 已合并为 `PATH`，不能靠画线检测表格；改用 `count_rects()` / `get_rect(i)` 的文本矩形几何（列簇+行带+数字占比）。
  - `get_rect()` 必须先调 `count_rects()`，否则静默返回空。
  - 一个单元格会拆成多个 text run（`'产品'`+`'9'` 间隙 1.1pt vs 列间隙 48pt），必须按水平间隙合并，否则 6 列变 7 列 —— P0 必做项。
  - 合成样本：69 矩形 → x 聚类 tol=20pt 还原 6 列；y 分带 tol=3~8pt 均为 10 行。
- 待办：P0（heuristic + normalize + 工具 + hint）→ P1（docling + 缓存）→ P2（跨页续表）。

`agent/SKILL.md`、`src/skills/doc-reader/SKILL.md`、`src/agent/context.py`。

关键实施决策（与设计稿的偏差，已回写设计文档）：
- 列切分从「x 中心聚类」改为「空白区间投影」：中心聚类在列内文本宽度差异大时会把一列碎成多列，
  且被稀疏列剔除后**整张表消失但仍报 status=ok**。投影法对齐无关，且同格碎片合并免费获得。
- envelope 的 `engine_degraded` 布尔 → `quality` 枚举（`geometric`/`structural`），
  `confidence` 恒为 null（几何引擎无法自评精度）。
- 缓存 key 不含调用方 `max_tables`，因此引擎固定抽到 _MAX_TABLES，缓存后再按调用方 limit 裁剪，避免小 limit 调用污染缓存。
- `to_dict()` 曾漏 `rows` 字段，导致缓存往返丢数据行 —— 被缓存测试抓到，已修。

测试：110 例通过（表格 83 + doc_reader 27），既有 doc_reader 全量零回归；合成 6 列表端到端 98ms。

关键决策：
- docling API 用官方文档+源码核对（`doc.tables` / `data.table_cells` / `*_row_offset_idx` / `column_header` /
  `prov[0].page_no`），`page_range=(first,last)` 为 1-based 闭区间；用 `inspect.signature` 探测而非 TypeError 兜底。
- **网格转换抽成纯函数 `build_raw_table(table, doc)`**，用鸭子类型假对象测——本机无 docling 也能覆盖合并/表头逻辑。
- 表体 `row_header` 跨行标签复制到被覆盖行（否则 CSV 有数无归属）；表头里的跨行 row_header **不**复制
  （否则顶掉 `flatten_columns` 需要的子表头名）——这个区别被测试抓到过一次真实错。
- 子进程：JSON over stdin/stdout，`PYTHONIOENCODING=utf-8`（Windows cp936 会毁中文），超时视为**错误**而非空结果。
- 惰性化 `tables/__init__.py` 试过又撤回：真正瓶颈是 `src/tools/__init__.py` 的 77 工具自动发现（~2.3s），
  子进程启动税无法从包内解决，已写进注释与设计文档。

未验证：本机未装 docling（torch + 1GB 模型），转换器管道未真机执行；首次装上后跑
`pytest agent/tests/test_table_docling.py -m integration` 验证。
