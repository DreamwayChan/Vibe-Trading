## 09:40 更正 tushare 结论 + L3 逐笔成交方向落地

**用户澄清**：配置里三个 tushare 账号都是 120 积分，且每分钟有请求限制。实测后**前一版文档的结论是错的**。

**实测（40203 原件）**
```
daily     ✅ 正常（批量 20/请求），全市场日线没问题
stk_mins  ❌ 同一天返回过三种措辞：
            「频率超限(2次/天)」→ 「1次/小时」→ 「1次/分钟」
          多重窗口同时限；3 账号 × 2 次/天 = 6 次/天
```
即「一次调用能跨多年」但**次数极少**，只能给 6 个标的补历史，不能全市场回补。
教训：**配额按调用次数计，不按行数**。之前看到 2842 根就断言"能任意回补"，是没算次数。

**tushare_pool 修的三处**
1. `is_daily_quota_error`（次/天 → 冷却到北京时间零点）、`is_per_minute_limit`（1次/分钟）、
   原先二者都被当成普通 RPM：冷却 65s 后换下一个 token → 一次请求烧光 3 个账号的当日额度。
2. `_API_MIN_INTERVAL_S = {"stk_mins": 61}`：按接口最小间隔，不够就换 token 而不是硬闯。
3. 跨进程账本 `~/.vibe-trading/lake/tushare_quota.json`（键=token 的 sha1 前 12 位，
   不能用 token_hint，短 token 会塌成 `***` 合并账号）+ `quota_report()` + 
   `TushareQuotaExhausted` / `TushareAllTokensBlocked` 两个明确异常。

**L3 逐笔（腾讯 gtimg，免费无积分）**
- 端点：`stock.gtimg.cn/data/index.php?appn=detail&action=data&c=sh600519&p=N`，70 笔/页
- 字段：`seq/time/price/change/volume(手)/amount(元)/side(B|S|M)`
- **只有最近一个交易日**（`d=` 被接受但忽略）→ 只能每日累积，和分钟线一样的命运
- 单标的单日：600519 4451 笔 / 64 页 / 13–20s
- 落库 `tick_agg`：active_buy_ratio / net_active_amount / big_amount(_ratio) / big_net_amount /
  trades / avg_trade_amount / vwap / open_auction_* / close_auction_* / post_close_* / prints_complete
- 脚本 `agent/scripts/build_ticks.py`：抓取 + **日线成交量对账**（>1% 告警）+ 不完整分页告警

**三个口径坑（都踩了）**
1. **收盘集合竞价是一笔 15:00:01 的批量成交**（600519：2546 手/3.54 亿）。按 `<=15:00:00` 过滤
   会当盘后丢掉 → 成交量少 4.24%。边界应为 `<15:01:00`。
2. 15:01 后确有零星笔（4 笔/16 手），是盘后固定价格交易，单独计入 `post_close_*`。
3. 主动买占比分母只用**有方向**的成交额，否则所有股票被压向 0.5，横截面失效。

**两次误判也一并修了**
- 首版按 `(time,price,lots,side)` 去重 → 删掉真实重复成交，量少 4%；改成按 `seq`。
- 短页（<70）不等于末页：真实尾部是 70,70,…,69,1；且 seq 会跳号（601318 从 4758 跳到 4760
  而成交量仍与日线一致）。所以「短页+前瞻」判完整性全是误报，改成只看异常/max_pages，
  完整性交给成交量对账。

**验收**：逐笔 vs 日线成交量 600519 +0.007%、000001 0.000%、8 只全部 ≤0.007%。
8 只横截面：主动买占比 0.427–0.639，与当日涨跌幅相关 0.704。

**环境**：venv 里 pip 被半升级坏掉（26.1.2 与 26.2.2 文件混装），已 `rm -rf pip*` + `ensurepip`
修复并装上 baostock 0.9.4。baostock 能取长历史 5m（74s/标的/季度），但重跑常卡死 >200s，
不适合日更，只适合过夜慢跑。

**测试**：`test_ticks.py` 18 + `test_tushare_pool.py` 23（新增 6 个配额用例，autouse fixture 
把账本隔离到 tmp_path），相关集合 263 passed。
