## IM 通道可用性优化方案（文档）

- 产出 `docs/design/im-channels-optimization.md`：现状根因 R1–R10 + 目标设计（Desired State / ChannelSupervisor / AuthSession）+ P0–P3 分阶段（6–8 人日）。
- 关键代码事实（已核对）：
  - 自动启动唯一开关是 `VIBE_TRADING_CHANNELS_AUTO_START`（`agent/src/config/env_schema.py:363`，默认 False），`agent/api_server.py:166` 使用，且无 try/except。
  - `ChannelManager.start_all()` 用 `await asyncio.gather(...)`，遇 `weixin.start()`（长循环，`weixin.py:486`）永不返回 → 启动后状态不刷新。
  - 微信绑定只有终端 ASCII 二维码（`weixin.py:428` / CLI `channels login`），无 REST/UI；token 落 `~/.vibe-trading/weixin/account.json`。
  - 配置只读 `~/.vibe-trading/agent.json`，无任何写入接口；`_get_channel_runtime()` 只加载一次配置（`agent/src/api/state.py:96`）。
  - 前端 Settings 仅状态表 + 全量 start/stop；`runChannelPairingCommand` 已定义但无调用点。
- 结论：缺的不是适配器，而是「期望状态持久化 + 绑定会话 API + 监督者」三块。
- 待办：P0 可立即动手（start_all 不阻塞、auto_start 默认开、单通道启停、状态机字段）。

## IM 通道 P3 实现（自愈 + 可观测 + 密钥外置）

- `channels/manager.py`：新增 supervisor
  - `_desired` 区分「操作员希望它开」与「它现在开着」，崩溃才重启、主动 stop 不重启；
  - `_run_channel` 退出时按 `_desired`/`needs_auth`/`is_running` 决定是否排重试；退避 1s→2s→…→60s，稳定运行 60s 后 `_reset_backoff`；
  - 自管后台任务的适配器（start() 返回但 `is_running=True`）不重启，避免无谓循环；
  - `_looks_like_auth_error()`：401/403/invalid_auth/errcode -14 直接 `mark_needs_auth`，不再重试；
  - `_respawn` 会重建适配器（旧实例可能留有半关闭的 client）；
  - 状态新增 `auto_restart/desired/backoff_s/retry_in_s`；`supervisor_running` 属性；
  - `channels.supervisor`（schema，默认 true）+ 每通道 `auto_restart`。
- `channels/logbuffer.py`（新）：`ChannelLogBuffer`（deque 200 条）+ `_BufferHandler`；`attach_logger` 同时挂 `src.channels.<name>` 与 `BaseChannel` 实例 logger；`reset()` 供测试。
- 路由：`GET|DELETE /channels/{name}/logs`；`runtime.channel_logs/clear_channel_logs`；status 里加 `supervisor`。
- `config/secrets.py`（新）：`secrets.json` 与 agent.json 同目录、0600、原子写；`split_secrets`/`store_channel_secrets`/`merge_secrets`/`clear_channel_secrets`。
  - `writer.set_channel_section` 把凭据拆到 secrets.json，并先把 agent.json 里的旧内联值迁过去再删除，`token: ""` 表示清除；
  - `load_channels_config()` 默认 overlay 回去，适配器无需改动；`include_secrets=False` 可看原始文件。
  - `auth.logout()` 现在会清 secrets 并停掉仍在跑的通道。
- 前端：`ChannelsPanel` 加「日志」按钮 + `ChannelLogsDrawer`（3s 轮询、级别配色、清空）；`api.ts` 加 `getChannelLogs/clearChannelLogs` 与字段；5 语言补 7 个文案键。
- 坑：`src/channels/logbuffer.py` 必须加入 `registry._INTERNAL`，否则 `discover_channel_names()` 会多出一个叫 logbuffer 的「通道」（已加）。
- 测试：`test_channels_lifecycle.py` 17 例（新增 backoff/监督者/日志/密钥分离/迁移/unbind 清理），`test_channels_api.py` 13 例（新增 logs 200/404），前端 SettingsChannels 6 例。后端通道相关 146+159 passed；`test_agent_config.py` 2 例与 `test_api_live_runtime.py` 1 例为 beartype/fastmcp 版本冲突导致的既有环境问题（非本次改动）。
